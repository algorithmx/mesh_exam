# Sample Mesh Fixtures (`e2e/sample_meshes/`)

Reference for the deterministic fixtures consumed by
`mesh_issue_examiner/tests/test_sample_meshes_e2e.py` and friends.  All
files are generated by `scripts/generate_sample_meshes.py` (no RNG), are
committed to the repository, and are only rewritten when their generator
constants change.  `scripts/generate_sample_meshes.py --verify` re-checks
every fixture against its CONTRACT (see the generator source) by running
the real inspection pipeline; the defective entries mirror
`DEFECTIVE_CASES` in the e2e tests.

A 2026-10 audit (`SAMPLE_MESH_AUDIT.md`) found several fixtures whose
geometry did not match what their names, docs, and test contracts claimed;
the affected fixtures were rebuilt and their constants were chosen by
`scripts/tune_sample_meshes.py`.  That history is summarised under
"Audit-driven changes" below.

## Intentional name mismatches

The "perfect" fixtures are named after the shapes they stand in for, not
the shapes they are.  Flat-faced polyhedra can never be zero-issue: the
diagonal split of each planar quad is an exactly-180-degree fold, and
trihedral corners have vertex valence 3.  The zero-issue stand-ins are
therefore deltahedra:

- `perfect_cube_surface` — gyroelongated square bipyramid ("gyro cube")
- `perfect_hexahedron` — octahedron (the only regular hexahedron that is a deltahedron)
- `pyramid` — pentagonal bipyramid
- `wedge` — icosahedron

Similarly, some defective fixtures are named for the operation they
exercise rather than their literal defect: `degenerate_triangle` contains
needle *slivers* (not degenerate triangles), `duplicate_vertices` contains
a duplicate *face*, and `perfect_tetrahedron` is a *flipped* tetrahedron.

## Audit-driven changes (2026-10)

`SAMPLE_MESH_AUDIT.md` recorded fixture/test mismatches; the fixes below
were applied.  Constants were chosen with `scripts/tune_sample_meshes.py`
(deterministic sweeps + full-pipeline verification).

- `torus` — the old tube had proper non-adjacent triangle crossings
  (pairs (30,33)/(31,34)/(32,35)) that the examiner's own detector missed
  and the generator never checked for.  Rebuilt with tuned constants;
  `verify()` now gates every zero-issue surface fixture on an independent
  proper-intersection check (`proper_intersection_pairs`) that does not
  use the detector under test.
- `icosphere_l1` / `icosphere_l2` — previously tripped only the
  edge-dihedral op; the tessellated contract demands cell-quality
  violations.  Re-tuned stretch (4.5) so `quality.compute_cell_quality`
  fires on both; the (40, 77) chord regression pair was re-validated.
- `self_intersecting` — the old geometry had zero proper crossings (a
  single-point contact); it is now the tent-over-floor proper crossing
  above.  The old geometry is preserved as
  `self_intersecting_point_contact`.  Both fire the detector, and
  `TestSelfIntersectionGeometry` pins the ground truth with an independent
  barycentric predicate.
- `multi_hole_plane` — the 4x4 grid forced the two holes to share the
  vertex (2,2,0), adding an unintended nonmanifold-vertex defect.  Now a
  5x5 grid with separated holes (cells (1,1) and (3,3)); boundary edges 28,
  no nonmanifold ops.
- `shell_structure` — both cubes were wound outward (signed volume 1.125,
  "two nested solids"), not a hollow shell.  The inner cube is now wound
  inward: watertight, signed volume 1 - 0.125 = 0.875, pinned by
  `TestClosedMeshes::test_shell_structure_is_hollow_shell`.
- `open_boundary` — was byte-identical to `perfect_square` (same SHA-256).
  Now a distinct 1x2 rectangle; `perfect_square` stays the unit square.

## Caveats and known limitations

- **Boundary-layer prism corner volumes:** the `boundary_layer` fixtures
  are documented (in `docs/inspection/`) to produce negative prism corner
  volumes under some signed-volume conventions.  This is a property of the
  corner-linearisation used by the quality metrics, not a fixture defect;
  documented only, no geometry change.
- **NASTRAN/Gmsh decks:** both are parsed by the native readers
  (`mesh_loader`), not meshio; round-tripping them through meshio may
  reorder or drop elements.  The fixtures are load-side only.
- **`isolated_vertices` is legacy VTK POLYDATA** (written through
  pyvista, unlike the VTU/XML files produced by meshio elsewhere; the
  file is `isolated_vertices_surface.vtk`, the only fixture whose file
  is not named after its directory). The e2e tests load it via
  `file_override`, and `tests/conftest.py` uses it as the session-start
  sentinel for self-healing generation.
- **Optional-dep fixtures:** `cgns_volume` / `exo_volume` are written only
  when h5py / netCDF4 is installed; their tests use `pytest.importorskip`.
  meshio's CGNS support is tetra-only, so CGNS carries the two-unit-tet
  mesh rather than the hex volume.

## Regenerating and verifying

    python scripts/generate_sample_meshes.py            # write missing fixtures
    python scripts/generate_sample_meshes.py --verify   # pipeline-verify all
    python scripts/tune_sample_meshes.py --quick        # validate built-in constants

The generator skips existing files, so after changing a fixture's
construction delete its directory under `e2e/sample_meshes/` (or use
`--force`, which rewrites every fixture including unchanged binary VTU
files).  `tests/conftest.py` generates missing fixtures at session start,
so a fresh checkout is self-healing.
